## 1 · 会话定义

| 项 | 定义 |
| :--- | :--- |
| **会话 A** | 3RScan 场景的 **reference scan**（首次建图） |
| **会话 B** | 同一场景的**某一次 rescan**（后续重访） |
| **配对约束** | B 必须是 A 的 rescan（`3RScan.json` 中 `scans[].reference`），**不能跨场景配对** |
| **坐标系** | 以 A 的坐标系为准。B 的物体位姿经该 rescan 的全局对齐矩阵 `transform` 变换到 A 系后再比较 |
| **物体身份** | 用数据集自带的 `objectId`。3RScan 保证同一物体在不同次扫描中 **ID 一致** |

> 数据集规模：**478 个场景 / 1004 次 rescan**（平均 2.10 次/场景，284 个场景有 ≥2 次重访）。
> 变更标注覆盖：`rigid` 982 次、`removed` 240 次、`nonrigid` 274 次 rescan。

## 2 · 真值类别（6 类）

脚本对 A∪B 中的**每个** `objectId` 输出唯一一类：

| 类别 | 判定依据 | 说明 |
| :--- | :--- | :--- |
| `unchanged` | A、B 都存在，且不在任何变更表中 | |
| `moved` | 在 `rigid` 表中（带 6DoF 变换） | 位移见 §4 |
| `nonrigid` | 在 `nonrigid` 表中 | 形变，无刚体变换 |
| `removed` | A 有、B 无，且列在 `removed` 表中 | 数据集的「消失」标注 |
| `absent_unlabelled` | A 有、B 无，**但不在 `removed` 表中** | ⚠️ 见 §5，**必须单独报** |
| `appeared` | B 有、A 无 | **推导得到**：数据集只标 removed，没有 added |

## 3 · 两个必须写死的约定（都是实测定的，不是猜的）

### 3.1 矩阵布局：平移在**最后一行**（行向量约定）

3RScan 把 4×4 存成 16 个行主序浮点数，但语义是 `p' = p · M`，**平移量在 `m[12], m[13], m[14]`**。

实测（用绝不会动的地板 / 天花板 / 墙做对照）：

| 采用的约定 | 结构物变换后的残差 |
| :--- | :--- |
| 行向量（平移在最后一行） | **0.03 – 0.32 m** ✅ |
| 列向量（平移在第 4 列） | 3.19 – 4.91 m ❌ |

### 3.2 物体变换的含义：`rigid[i].transform` **已经包含会话对齐**

这条最容易搞错。实测（5 个移动物体）：

| 检验 | 残差 |
| :--- | :--- |
| `T · c_A` 对比 `c_B` | **0.014 – 0.112 m** ✅ |
| `T` 的平移量直接当作物体位移 | 1.15 – 3.03 m ❌（含约 1.6 m 的扫描原点偏移） |

**结论**：T 把物体从 A 系直接映射到 B 系，其平移量**不是**物体在房间里的位移。
真实位移要把会话间偏移扣掉：

```
motion = | M · T · c_A  −  c_A |          （在 A 系中表达）
```

因为 M 是刚体变换，这与 `|T·c_A − M⁻¹·c_A|` 等价。

## 4 · 容差半径：**不能取 0.5 m**

在 26 个 `unchanged` 物体上测量会话对齐的残差（即标注噪声下限）：

| 统计 | 数值 |
| :--- | :--- |
| 平均 | 0.151 m |
| p95 | 0.528 m |
| **最大** | **0.639 m** |

> ⚠️ **结论**：题目文档 §8 里默认的 **0.5 m 容差偏小** —— 噪声最大值 0.639 m 已经超过它，
> 意味着一个**没动过的物体**仅凭对齐误差就会被判成「移动」。
> **本协议取 1.0 m**（> 噪声上限，且远小于本对中最小的真实位移 0.265 m 的 4 倍）。
> 换场景后必须**重新标定**这个数，不能沿用。

## 5 · 已知的数据集缺口（必须写进报告）

### 5.1 `absent_unlabelled`：消失了，但数据集没说它被移除

本对中 **id=23（cushion）**：出现在 A 的实例标注里，B 的实例标注里没有，
但**不在** `removed` 表中。

两种解释，数据集没有区分：
1. 这个垫子真的被拿走了；
2. 它在 B 里仍然存在，只是**没有被分割出来**（分割不完美）。

**这正是那道题目要解决的问题本身** —— 所以它不能被并进 `removed`，也不能被丢掉，
必须作为独立类别报告。任何把它算作 `removed` 的评测都会**高估**自己的性能。

### 5.2 数据集没有 `added` 表

`appeared` 只能由「B 有、A 无」推导。代价是：如果 A 的分割漏掉了一个一直存在的物体，
它会被误判成 `appeared`。**与 5.1 是同一枚硬币的两面。**

### 5.3 数据集不标注可观测性

3RScan 不提供「这个物体在本次会话中是否在视场内 / 是否被遮挡」。
这意味着：**这套 GT 只能验证「变化检测准不准」，无法直接验证「系统是否知道自己在不确定」。**
要检验可观测性假设（X1 / H1a），必须**自己造遮挡与部分视角** —— 见 §7。

## 7 · 可观测性分层（已实现）

**这是数据集给不了、必须自己算的那一半。** 3RScan 只标注「什么变了」，
从不标注「机器人当时能不能看到」。这两件事的差别就是「垫子被拿走了」与「我没看那个垫子」。

方法（`work/observability.py`，逐物体 × 逐帧）：

```
物体采样点（B 系）→ 相机系 → 像素 + 预测深度
  实测深度 ≈ 预测深度  →  这个面被看到了        （visible）
  实测深度 << 预测深度  →  前面有东西挡着        （occluded）
  没有点落进画面       →  不在视场内              （out_of_view）
```

按整个会话聚合（不是按单帧）：51 帧里被确认看到 1 次，和 30 次不是一回事。
判定阈值：`min_samples=3`（一帧内至少 3 个采样点吻合）、`min_visible_frames=3`。

### 7.1 两个约定同样是实测定的

| 约定 | 结论 | 怎么证 |
| :--- | :--- | :--- |
| **相机位姿** | `p_world = R p + t`（平移在第 4 列） | 帧间重投影：该读法与实测深度的偏差 **97.3% < 5 cm**；另一种读法只有 **14.8%** |
| **OBB 轴向** | `normalizedAxes` 的**行**是三个轴向量，轴 k 的半长 = `axesLengths[k]/2` | 地板/天花板的**最薄轴必须指向世界 z**、墙的最薄轴必须等于其 `dominantNormal` —— 只有按行读才成立 |
| **深度单位** | PGM 存的是**毫米**，`m_depthShift` 是**除数**不是乘数 | 读反了深度会大 1000 倍，所有表面都变成「实测远在预测之后」，`visible` 类被静默清空（这个坑踩过并已加回归检查） |

### 7.2 本机结果（会话 B 的 51 帧）

| gt_class \ observability | visible | occluded | out_of_view | insufficient |
| :--- | ---: | ---: | ---: | ---: |
| unchanged | 6 | 4 | 13 | 3 |
| moved | 3 | 0 | 2 | 0 |
| **absent_unlabelled** | **0** | **0** | **1** | 0 |

**核心结果**：那个「消失了但没被标成 removed」的垫子（id=23），
它的预期位置在会话 B 的 51 帧里**从未进入视场**。

→ 因此**不能**把它的消失读作「被移除」。这正是 H1a 预测的失败模式：
**未观测 ≠ 不存在**，而且这个混淆在数据集里是**隐式**的 —— 它既不标注、也不提示。

> ⚠️ **必须声明的限制**：公开示例包只包含整段轨迹的**前 51 帧**（会话 B 声明 753 帧，
> 会话 A 声明 520 帧）。所以 `out_of_view` 的含义是「**在采样的这些帧里没进视场**」，
> 不是「整个会话里都看不到」。随着机器人继续走，那个位置很可能被看到 ——
> 拿到全量序列后这个结论要重新算。
