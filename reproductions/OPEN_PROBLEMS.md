## 为什么不收敛

「好像现在都比较收敛」——这个判断在**指标层面**是对的。KITTI 与 EuRoC 上的 ATE 已经卷到小数点后三位，
地点识别卷 Recall@1，地图清理卷 SA/DA/AA，神经 SLAM 卷渲染质量。这些榜确实在收敛，而且越来越难做出差别。

但把 87 条候选按**它们自己在论文里承认没解决的问题**排一遍，空白集中在下面几处，
而这几处**都不是「精度不够」**：

| 已经收敛的 | 还没有收敛的 | 对应簇 |
| :--- | :--- | :--- |
| 单一序列上的 ATE / RPE | 指标与**下游后果**的对应关系：Recall@1 高不代表这次闭环有好处，ATE 低不代表任务成功 | 09 · 10 |
| 一次运行的精度 | 地图的**生命周期**：结构变了以后该改哪一块、什么时候该退役一个子图、证据要攒到多少才算数 | 01 · 08 |
| 点级 / 帧级的分类准确率 | **不确定度的校准**：输出的协方差到底是不是协方差（χ² 检验过不过） | 05 · 12 |
| 干净标注下的语义先验 | 先验**被污染**时的临界点：标签错 30% 时语义图还剩多少价值 | 06 · 07 · 14 |
| 离线静态场景上的理解 | **在线图**上的推理：节点会漂、会过分割、会漏，变化预测器还能不能用 | 08 |
| 单机 | 多机的**通信预算**：一个字节到底买到多少精度 | 13 |
| 某一种传感器上的方法 | 同一套先验**跨模态**复用：换传感器是不是必须重调 | 11 · 02 |

> **一句话**：收敛的是「在给定口径下把数字刷高」，没有收敛的是**口径本身**。
> 这 14 个问题里有 9 个的开放原因是**评测或形式化**，不是算力 —— 也就是说，它们不需要 GPU 也能推进。

## 这 14 个问题是怎么选出来的

每条都必须同时满足四条，缺一条就不进这一页：

| 条件 | 为什么 |
| :--- | :--- |
| **能被证伪** | 每条都写了「什么结果会把它推翻」。想不出证伪条件的问题不是问题，是一句感慨。 |
| **一个人下周能开工** | 不写「需要一个大团队三年」的方向。脚手架列的是真实可达、实测 HTTP 200 的仓库。 |
| **只靠公开数据** | 至少 12 条如此。剩下 2 条的瓶颈写明了是神经网络算力，不是数据。 |
| **和已列的 8/10 个难点能对上，或者是新空白** | 表里逐条标了「攻击的是哪个已列难点」；对不上的就是新空白（多机协同、主动 SLAM）。 |

### 01 · 地图结构变更的证据判据

*Evidence thresholds for map structure change*

|  |  |
| :--- | :--- |
| **开放问题** | 需要多少、何种一致性的重复观测，才足以把一辆已停稳的车并入静态地图，或把某个旧子图退役？该阈值能否跨数据集迁移？ |
| **为什么还开放** | 缺少“变化真值”：现有动态基准只评动态点删除，不评该保留/该退役的结构；阈值与场景、传感器强耦合，各论文自行手调。CPU+公开数据可做。 |
| **上手门槛** | 🟢 CPU · 公开数据 |
| **可用脚手架** | [Yixin-F/LiLoc](https://github.com/Yixin-F/LiLoc) · [hku-mars/LTAOM](https://github.com/hku-mars/LTAOM) · [PRBonn/MapClosures](https://github.com/PRBonn/MapClosures) · [PRBonn/kiss-slam](https://github.com/PRBonn/kiss-slam) |
| **最小实验** | 在 KITTI 00 上取一段手工标注为“先动后停”的车辆点，把 revisit 计数从 1 扫到 10，记录并入静态地图后的局部配准残差与误删率，画出阈值曲线。 |
| **证伪条件** | 若同一 revisit 阈值在 KITTI/MulRan/NCLT 上给出相同的误删-漏删曲线，则这只是调参问题而非开放问题。 |
| **与已有 21 条的关系** | 已有 KISS-ICP/LT-mapper/ERASOR 但都只做“删动态”；难点3 只谈权重遗忘，这条问的是地图层退役判据，是新问题。 |

### 02 · 单线雷达能否监督动态检测

*2D lidar as dynamic-label supervision*

|  |  |
| :--- | :--- |
| **开放问题** | 由单线 2D 雷达高度切片自动生成的动态/静态标签，作为 3D 动态检测评测的真值代理时，与人工标注的一致率是否足以支撑评测？ |
| **为什么还开放** | 没有适配 D435i+单线雷达的公开数据集；一层扫描看不见蹲伏、低矮与高处物体，代理标签的漏检率从未被量化。CPU+公开数据可做。 |
| **上手门槛** | 🟢 CPU · 公开数据 |
| **可用脚手架** | [ethz-asl/dynablox](https://github.com/ethz-asl/dynablox) · [NEU-REAL/OTD](https://github.com/NEU-REAL/OTD) · [PRBonn/kiss-slam](https://github.com/PRBonn/kiss-slam) |
| **最小实验** | 把 KITTI/DOALS 的点云压成一层水平扫描以模拟 2D 雷达，自动生成动态标签，与人工动态标注求 F1，再用 Dynablox 与 OTD 交叉验证同一批标签。 |
| **证伪条件** | 若代理标签与人工标注的 F1 差距小于 5%，则“必须有 3D 真值才能评测动态检测”这一前提不成立。 |
| **与已有 21 条的关系** | 正对用户自列的“传感器非标、无公开数据集、无现成基线”；已有 ERASOR/DUFOMap/BeautyMap 全部假设 3D 雷达，属全新问题。 |

### 03 · 神经表征的增益归于何处

*Neural map gains vs compute budget*

|  |  |
| :--- | :--- |
| **开放问题** | 神经地图 SLAM 相对几何基线的精度优势中，有多少来自地图表示本身，多少来自只有 GPU 才负担得起的迭代与采样预算？ |
| **为什么还开放** | PIN-SLAM 的 CPU 模式只承诺“更慢”，仓库与论文都没有 CPU 基准；MonoGS 等强制 CUDA，无法在 20 核机器上提供对照。 |
| **上手门槛** | 🟡 CPU 模式可跑 · 要 GPU 才公平 |
| **可用脚手架** | [PRBonn/PIN_SLAM](https://github.com/PRBonn/PIN_SLAM) · [muskie82/MonoGS](https://github.com/muskie82/MonoGS) · [PRBonn/ir-mcl](https://github.com/PRBonn/ir-mcl) |
| **最小实验** | 在 KITTI 00 的 100 帧子集上把 PIN-SLAM 的 CPU 迭代数与采样数按 1/4、1/2、1 倍扫描，画精度-耗时曲线，并与同数据上的 KISS-ICP 对照。 |
| **证伪条件** | 若迭代预算砍到 1/4 后精度跌幅小于 2%，说明增益来自表征而非预算，“神经 SLAM 慢”就不是精度借口。 |
| **与已有 21 条的关系** | 正是用户自列的“难点2 神经 SLAM 实时性没有任何复现条目”；PIN_SLAM 的 CPU 模式是唯一可给出对照的入口。 |

### 04 · 隐式地图能否跨传感器季节

*Cross-sensor, cross-season implicit map reuse*

|  |  |
| :--- | :--- |
| **开放问题** | 用 A 平台或 A 季节数据训练出的隐式神经地图，对 B 平台或 B 季节的查询是否仍给出可用的观测似然，还是必须重训？ |
| **为什么还开放** | ENM-MCL 的观测模型只在同一平台、同一建筑、同一场次内测过；IR-MCL 的 NOF 逐环境训练，跨域退化曲线无人测量。CPU+公开数据可做。 |
| **上手门槛** | 🟢 CPU · 公开数据 |
| **可用脚手架** | [PRBonn/enm-mcl](https://github.com/PRBonn/enm-mcl) · [PRBonn/ir-mcl](https://github.com/PRBonn/ir-mcl) |
| **最小实验** | 用 IR-MCL 在公开 2D 数据集 A 上训练 NOF，直接对数据集 B 跑 eval.py 定位，统计成功率与似然校准，再与在 B 上重训的对照组比较。 |
| **证伪条件** | 若跨域与同域的定位成功率、似然校准差距均小于 10%，“神经地图必须逐环境重训”的假设被推翻。 |
| **与已有 21 条的关系** | 与难点3（终身 SLAM 遗忘）相邻但不同：这里问表示层的域漂移，不是权重遗忘；21 篇中没有隐式定位地图条目。 |

### 05 · 回环位姿的不确定度能否标定

*Calibrating loop-closure pose uncertainty*

|  |  |
| :--- | :--- |
| **开放问题** | 由内点率或最大团导出的信息矩阵，能否被标定到与实测误差一致（χ² 检验通过），使位姿图不必再把回环当作精确约束？ |
| **为什么还开放** | KISS-Matcher 与 G3Reg 都只输出单一最优位姿、无协方差；PALoc 的 README 自认代码中“相对位姿逆的伴随”有未修复错误，连约定都不统一。CPU+公开数据可做。 |
| **上手门槛** | 🟢 CPU · 零下载 |
| **可用脚手架** | [MIT-SPARK/KISS-Matcher](https://github.com/MIT-SPARK/KISS-Matcher) · [HKUST-Aerial-Robotics/G3Reg](https://github.com/HKUST-Aerial-Robotics/G3Reg) · [mit-acl/dpgo](https://github.com/mit-acl/dpgo) · [JokerJohn/PALoc](https://github.com/JokerJohn/PALoc) |
| **最小实验** | 在 KITTI 上用 KISS-Matcher 生成带离群回环的位姿图，分别以单位阵和内点率导出的信息矩阵求解，比较 ATE 与 χ² 一致性指标。 |
| **证伪条件** | 若两种权重给出相同 ATE 且 χ² 检验都通过，则“回环需要不确定度”这一动机不成立。 |
| **与已有 21 条的关系** | 已有 KISS-ICP/GenZ-ICP 但都无不确定度输出；PALoc 的伴随（adjoint）bug 是本次扫描新发现，不在用户已列清单内。 |

### 06 · 语义先验被污染时的临界点

*Semantic graph vs geometry under label noise*

|  |  |
| :--- | :--- |
| **开放问题** | 当语义标签按给定噪声率被腐蚀或整类缺失时，语义图 SLAM 在哪一点开始不如纯几何后端？该临界点是否随场景类别分布移动？ |
| **为什么还开放** | SG-SLAM 依赖离线 SegNet4D 标签，论文从不量化标签噪声与缺失下的退化；TripletLoc 只支持五类，标签降级后的成功率无人测。CPU+公开数据可做。 |
| **上手门槛** | 🟢 CPU · 公开数据 |
| **可用脚手架** | [nubot-nudt/SG-SLAM](https://github.com/nubot-nudt/SG-SLAM) · [Weixin-Ma/TripletLoc](https://github.com/Weixin-Ma/TripletLoc) |
| **最小实验** | 在 SemanticKITTI 上按 0/10/30/50% 随机翻转标签并做整类删除，重跑 SG-SLAM 的图优化，画 ATE 与回环成功率随噪声率的曲线。 |
| **证伪条件** | 若标签噪声 50% 时 ATE 与干净标签相差小于 5%，则语义图对先验污染极鲁棒，临界点问题不成立。 |
| **与已有 21 条的关系** | 与难点1（语义先验盲区）同源但方向相反：那里是检测不到，这里是先验被污染；21 篇无一篇做标签噪声消融。 |

### 07 · 开放词汇实例能否跨回环保身份

*Instance identity across loop closure*

|  |  |
| :--- | :--- |
| **开放问题** | 回环或重访发生时，开放词汇实例的 ID 与其文本嵌入是否稳定，还是发生静默的身份交换？身份交换率能否被度量？ |

| **证伪条件** | 若回环前后实例 ID 交换率与无回环基线无显著差异，则身份不稳定并非真问题。 |
| **与已有 21 条的关系** | 对应难点5/6（开放词汇建图与场景图时间一致性）；已有 HOV-SG、concept-graphs 都是离线图，在线身份持久性无人做。 |

### 08 · 变化预测能迁移到在线场景图吗

*Change prediction on online SLAM graphs*

|  |  |
| :--- | :--- |
| **开放问题** | 在 3DSSG 干净标注上训练的变化预测器，面对 SLAM 在线产出的过分割、漏检、节点漂移的图时，精度掉多少，还能定位到真正会变的对象吗？ |
| **为什么还开放** | 3D VSG 只在静态扫描的规整图上评测；vS-Graphs 的层次止于房间、没有物体层；在线图的节点既不完整也不稳定，这一分布差距从未被量化。CPU+公开数据可做。 |
| **上手门槛** | 🟢 CPU · 公开数据 |
| **可用脚手架** | [ethz-asl/3d_vsg](https://github.com/ethz-asl/3d_vsg) · [snt-arg/visual_sgraphs](https://github.com/snt-arg/visual_sgraphs) · [boschresearch/Open3DSG](https://github.com/boschresearch/Open3DSG) |
| **最小实验** | 把 3D VSG 的预训练模型直接跑在 Hydra 或 vS-Graphs 输出的图节点上，按节点对齐率分层统计变化预测 AUC，并与 3DSSG 原始图对比。 |
| **证伪条件** | 若在节点过分割两倍的情况下 AUC 跌幅小于 0.05，则变化预测对图噪声不敏感、迁移障碍不存在。 |
| **与已有 21 条的关系** | 用户已有 3RScan 与 HOV-SG 数据链，缺的正是“在线图噪声”这一环；对应 D2 的变化与维护方向，属新问题。 |

### 09 · VPR 指标能否预测闭环后果

*Do VPR metrics predict loop-closure outcome?*

|  |  |
| :--- | :--- |
| **开放问题** | Recall@1 的高低能否预测一次错误回环造成的 ATE 恶化幅度与恢复距离？是否存在比 Recall@1 更贴近下游后果的可测指标？ |
| **为什么还开放** | aero-vloc 综述明确指出从未测量错误匹配如何传播进位姿图；BoWG 与 SOLiD 只报检索指标，不报闭环后的轨迹后果。CPU+公开数据可做。 |
| **上手门槛** | 🟢 CPU · 公开数据 |
| **可用脚手架** | [EdgarFx/BoWG](https://github.com/EdgarFx/BoWG) · [sparolab/SOLiD](https://github.com/sparolab/SOLiD) · [haomo-ai/OverlapTransformer](https://github.com/haomo-ai/OverlapTransformer) · [prime-slam/aero-vloc](https://github.com/prime-slam/aero-vloc) |
| **最小实验** | 在同一后端上，按不同 VPR 描述子给出的候选注入假回环，记录 ATE 恶化峰值与恢复帧数，与各描述子的 Recall@1 排名做秩相关。 |
| **证伪条件** | 若 Recall@1 排名与“注入假回环后 ATE 恶化”排名完全一致，则现有 VPR 指标已足够，无需新协议。 |
| **与已有 21 条的关系** | 正是用户自列的“难点7 有基线、无评测协议”；已有 AnyLoc、Revisit-Anything 只做检索，从未接回后端量化后果。 |

### 10 · 能否在失效前预判退化

## 这一页是怎么产生的

- 输入：[`CANDIDATES.md`](CANDIDATES.md) 里的 87 条候选，每个仓库都实测可达、元数据是抓下来的真实值。
- 过程：先按方向独立检索，再把每条候选自己承认的「未解决问题」抽出来，去重、合并、按可攻击性排序。
- 自检：14 条里用到的 42 个脚手架仓库**全部**能在候选表里找到，没有一个是编造的；
  没有任何两条簇共用同一个底层问题（「动态→静态的晋升」与「旧子图退役」已合并成一簇，没有重复计数）。
- 局限：所有的「为什么还开放」都是**从论文与仓库文本推断的**，不是实测结论。
  按本仓库的规矩，它们要变成结论，得先变成 `reproduce.py` 里的一条 `checks`。
