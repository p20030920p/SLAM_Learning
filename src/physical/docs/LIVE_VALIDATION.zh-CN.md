## 2. 原始数据与显示检查

- 相机实测 D435，USB 3.2，四路 640×480@30；无 IMU。带原始录制的 12 秒会话经 SDK 单路回放：左右 IR 各 351、深度 350、RGB 347 条消息，与 SQLite 文件计数全部一致，实时观察过的帧号全部存在。采集循环读到的同步帧组较少，不等于原始录像只保存了这些帧。
- 雷达重新插接后自动解析到实体 Serial3，读出 YS-L2、固件 2.8.8.1。12 秒记录收到 2,594 线包、2,997 IMU 包、744,435 有效点；CRC、序号缺失、倒退均为 0。后续 8 秒记录有 1 个 CRC 拒绝，已拒绝进入算法，不能说所有短测均为零错误。
- 50 线聚合约 4.3 cloud/s，主机线包/IMU 约 216/250 Hz。原始设备时间拟合比例仍约 2；未修复时钟，不启用 LIO、去畸变或相机—雷达融合。
- 真实 WSLg RViz 启动检查覆盖 camera_odom、camera_map、lidar_odom、lidar_raw；没有 OpenGL/插件加载失败。另用隔离 Xvfb 实际检查渲染像素，确认 RGB、深度、IR、点云，以及修正后的状态文字能显示。截图位于本机 `.cache/rviz-camera-raw.png`，不上传室内原始画面。
- RViz 的 `Stereo is NOT SUPPORTED` 是显示器立体渲染提示，本机普通三维画面仍可显示。相机 LOST 时出现点云 TF 队列满，反映当前没有可用连续位姿，不应据此假装地图完整。

## 3. 性能与软件修正

相机硬件配置 30 fps，桥接设置 10 fps 上限；实际约 4–6 组/s。最后一段 RGB-D 输入 4.20 Hz、原生计算 p95 62.8 ms；ICP 输入 4.31 Hz、原生计算 p95 169.5 ms；KISS 隔离进程往返计算 p95 132.5 ms。其它研究作业也在本机运行，未隔离负载，这些只作本轮运行观察。桥接/渲染完整端到端延迟未量化。

修正并保留原失败的事项：

1. 启动首对左右 IR 曾有 >1 ms 时间差；现在计数并跳过，原始录像保留，不把不匹配双目对发给算法。
2. PowerShell 5.1 的辅助进程 ExitCode 可能为 null，曾误报成功收流会话失败；现在读取结果清单判执行状态。
3. Windows 与 WSL 系统时间有偏差；ROS 统一使用 WSL 接收时刻并保留流间原生偏移。不能用两套系统时钟差当传输延迟。
4. 早期 RGB-D 覆盖只匹配彩色时间戳，算法选深度时间戳时低估覆盖；现在允许二者之一在 1 微秒内一一匹配。旧清单保留当时数值，不拿错误的 4.3% 作为新的算法成绩。
5. RViz 状态显示改为 Humble 的 Topic 属性，实际渲染确认可见；默认只开 RGB/深度面板，左右 IR 可勾选切换。

8 项软件测试通过：混合 RGB/深度/点云传输无损、截断帧/过大载荷/不一致布局拒绝、RGB-D 双时间戳匹配、输出一一对应、时间容差及空输出。Windows Python 编译检查和实际 PowerShell 5.1 环境检查通过。最后三次会话的 `code-hashes.json` 保存启动时脚本/配置哈希；更早会话没有该功能，证据中留 null，未补造当时版本。

原始录像改为流式计算哈希，避免 60 秒大文件整段载入内存；收流完成后先关闭发送方向，再做本地校验，避免校验时间误触发 ROS 收流超时。最后 6 秒带原始录制会话正常结束，文件 SHA-256 与 Windows 独立校验一致。

正式启动脚本结束时只清理自己启动的算法和 RViz，超时定向终止，不关闭其它研究任务。临时截图辅助程序曾有一次退出超时，已定向清理；截图检查不等于正式退出流程测试。会话完成后检查没有本分支桥接/算法残留。

下一步严格按[测试计划](TEST_PLAN.zh-CN.md)做受控固定、尺量和移动，不把本轮“入口能跑”当成定位问题已解决。
