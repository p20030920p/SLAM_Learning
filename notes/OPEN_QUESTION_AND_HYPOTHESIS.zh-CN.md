# 历史位姿修正后，开放词汇地图如何恢复可信的目标坐标？

[English](OPEN_QUESTION_AND_HYPOTHESIS.md) | 中文

[个人索引](README.zh-CN.md) · [实验室要求与简稿](LAB_ANALYSIS.zh-CN.md) · [原始复现结果分析](AUTHOR_RESULTS_ANALYSIS.zh-CN.md)

2026-10-09。本文是已填写的研究论证稿，供阅读原文、手动复跑和面试准备时修改。作者基线和探索实验已经执行；下文提出的恢复模块与新验证实验尚未实现或运行。基础设备检查见[实物分支](https://github.com/p20030920p/SLAM_Learning/tree/Personal-Learning-Physical)；本页恢复与四事件研究试验未完成。

## 1. 可以直接使用的简洁版本

我选择动态环境中的鲁棒定位与 SLAM，以及语义建图、视觉定位与导航，并将研究范围收窄到二者之间的接口：位姿变化如何影响地图中的对象对应与语言查询坐标。DUFOMap、BeautyMap 用空间证据清理动态地图，ConceptGraphs、HOV-SG 将观测融合为可查询的三维表示；它们提供不同的决策接口，不能用同一分数排名。

复现结果没有支持“四种方法都因位姿误差失效”的强判断。DUFOMap 表 IV 的 15 项 SA/DA/AA、BeautyMap 表 III 的 9 项 SA/DA/HA，均匹配论文两位小数，说明作者已有的误差保护和参数取舍必须成为强基线。

早期子集压力测试中，同为 30 cm RMS，DUFOMap 在单调漂移下的静态保留反而好于打乱误差；HOV-SG 的已标表面覆盖仍较高，受限语言查询却下降。这提示局部几何一致、对象关联和世界坐标有效性应分别评价，不能把地图看起来完整等同于目标可靠。

**开放问题是：历史位姿后来被修正时，在有限观测缓存下，怎样判断哪些对象对应需要重算，恢复正确的对象身份和查询坐标，并及时停止输出仍被标为有效的过期坐标？**

我的候选假设 H1 是：保存观测来源、位姿版本和窗口前检查点，在修正后先标记受影响结果，再重放必要的观测及关联决策，比仅修正几何、冻结关联更能接近完整历史重建的结果。首先在 ConceptGraphs 上验证这一点，固定图像、掩码、特征和评价协议，同时报告身份错误、坐标误差、查询覆盖、恢复延迟与内存。

若几何修正已经达到同样效果，或简单阈值保护取得同样的风险—覆盖—延迟前沿，就应放弃额外关联恢复的收益主张。现有结果只是提出这一问题的依据，还不是 H1 有效性的证明。

## 2. 为什么值得问，已有工作解决了什么

选这四篇的理由是能够追踪“给定位姿 → 空间对应 → 地图决策 → 查询结果”这条链，而非声称覆盖完整 SLAM。当前运行使用提供的位姿，没有估计轨迹或测量 ATE/RPE，也没有完成机器人导航评价。

| 工作 | 已有机制与本问题的关系 | 本研究需要单独测的部分 |
| --- | --- | --- |
| [DUFOMap](https://arxiv.org/html/2403.01449v1) | 已对自由空间判定加入传感器／位姿误差容差；不能把“考虑误差”写成新贡献 | 后来修正历史位姿，是否需要重建已有自由空间决策；原 API 尚无经验证的局部逆积分 |
| [BeautyMap](https://arxiv.org/html/2405.07283v1) | 已有占据、射线修正和保护；网格大小影响静态保留与动态剔除 | 固定可见性与参数后，历史对应修正是否还有独立收益 |
| [ConceptGraphs，II-A](https://arxiv.org/html/2309.16650v1) | 几何重叠和语义相似度决定贪心关联，再融合点与特征 | 只移动融合点能否修复先前的误合并／碎片，还是需要回放关联 |
| [HOV-SG，III-A、V](https://arxiv.org/html/2403.17846v2) | 用里程计把分段投到全局后合并；作者明确讨论静态环境和耗时限制 | 离线分段与查询能否恢复；在线更新接口必须另行实现，不能直接声称低延迟 |

更接近的先验工作构成实质挑战。[Khronos，IV、V-B/C、VII](https://arxiv.org/html/2402.13817v2) 已联合处理位姿、片段与背景，进行地图协调，并区分遮挡和缺少物体的证据；作者也讨论持续保留片段的内存增长。

[DovSG，III-D](https://arxiv.org/html/2410.11989v2) 已通过重定位、几何细化和局部记忆更新适应变化。因此，“有历史”“支持动态更新”“回滚”“共享位姿”都不能单独作为原创贡献。

候选贡献更窄：**针对开放词汇查询，把迟到位姿修正后的关联恢复、来源缓存范围、结果有效性和拒答成本放进同一个可测接口。** 这是需要实现和继续查证的新颖性候选，不是“文献中无人解决”的结论。Khronos、DovSG 目前仅做文献比较，未被复现为实验基线；缺少这些实测比较时，不声称优于现有动态语义系统。

## 4. 问题的操作性定义

输入是固定的 RGB-D／点云观测、标定、缓存前端特征，以及逐次到达的位姿版本。一次迟到修正改变过去若干观测的位姿，可能改变它们与历史对象的几何重叠和归属。输出为查询目标的对象记录、坐标、坐标系、来源位姿版本、最近支持时间和状态：有效、暂定、过期或不可恢复。版本一致不代表物体仍存在，状态仍须结合可见性和新观测。

需区分三类错误：**对象正确但坐标错误；坐标附近有几何但对象身份错误；物体已移动／移除，系统仍把旧坐标当作有效答案。** “所有受影响结果立即拒答”可以缩短过期暴露，却损失覆盖，必须计入代价。稳定背景不可观测时，相机漂移和物体同向运动可能不可辨识，应返回未知并记录覆盖损失。

完整历史重建 B5 是“相同作者核心在修正输入上的参考结果”，仍可能有语义和关联错误，不能替代独立物体真值。必须同时报告与 B5 的一致性和对独立参考的质量；恢复到错误的 B5 不能算任务成功。

## 5. H1：先检验关联恢复，再检验共享不确定性

**H1-R（首要、可先实现）：**当修正涉及的观测及关联依赖均在可恢复范围内时，从修正前检查点回放关联与融合，比只重投影并冻结关联更接近 B5，并改善独立标注的身份／坐标质量；其增益在匹配查询覆盖和恢复延迟后仍有价值。该预测尚未验证。

最小实现先针对 ConceptGraphs，缓存原深度、压缩掩码、逐掩码特征、帧号、位姿版本及关联来源。修正到达后先标记相关查询，恢复窗口前检查点，再按固定顺序重放。关联影响可能传播到竞争候选、相邻对象与后续融合，不能只回放被改位姿的几帧。第一版宁可回放整个保留窗口；局部回放只有在验证依赖闭合后才启用。

候选来源缓存为最近 16 个观测、最多 512 MiB，先触及哪个上限就停止接纳或逐出并记录。**该数值只是设计目标，只约束来源缓存；检查点、索引、作者地图、进程 RSS 和显存另行计费。** 未证明系统总内存有界。检查点早于最早修正、状态可重建、贡献者与候选依赖完整，是精确恢复的必要前提；否则全量重建或明确不可恢复，不用近似结果冒充精确撤销。窗口外修正是正式失败条件，不隐藏。

**H1-U（第二阶段）：**在来源、回放、预算和提交策略相同的条件下，显式建模同一位姿引入的联合几何误差，比独立方差近似取得更好的风险—覆盖—延迟前沿。共享版本号本身不是联合不确定性模型；同帧点受到共同变换，但相对几何中的部分误差可能抵消，不能一律视作额外风险。只有实现明确估计器、检查校准后才能检验 H1-U；已知注入误差／协方差属于 oracle，单独报告。余弦分数不当作正确概率。

两项假设分开接受或否定。H1-R 成功不证明 H1-U 成功；版本状态接口按设计运行，也不自动说明恢复算法更准确或具有新颖性。

## 6. 可在这台电脑上开展的检验

先用已有 Replica 缓存调试，再冻结新的房间／设备会话作测试。D435 固定于三脚架，分别采集静止、遮挡、移动和可见移除；L2 独立做同类几何试验，暂不把两个设备当成已标定融合系统。详细采集步骤见 [居家操作](HOME_RUNBOOK.zh-CN.md)和 [实验协议](../docs/REAL_WORLD.zh-CN.md)。原生加载检查已有记录，实物语义核心和研究评价尚未完成。

恢复压力测试从同一片段抽取 40 个观测，保持前端不变：观测 8–15 注入世界 x 方向 0→10 cm 线性偏差，在观测 16、24、36 到达时交付历史修正。它是确定性干预，不冒充真实定位误差分布。按“缓存最近 16 个已处理观测、收到修正后再处理新观测”的顺序固定边界；三种延迟分别测试窗口内和跨窗口恢复。记录真实 RMS、修正内容、观测顺序和所有逐出事件。

| 条件 | 用来排除什么解释 |
| --- | --- |
| B0 原核心，不处理历史修正 | 测量不恢复的后果 |
| B1 简单阈值／可见性保护 | 排除仅靠保守参数就能达到同样效果；参数在验证会话选择后冻结 |
| B2 相同原观测重投影，冻结原关联 | 隔离几何修正本身的收益 |
| B5 修正位姿后的完整历史重建 | 给出同核心的恢复参考，同时测独立真值与实际成本 |
| B3 独立方差保护 | 第二阶段的同预算对照；须明确并校准估计器 |
| B4 完整候选 | 必须拆出下列组件，避免将两项变化归为一个原因 |

先完成 B0/B1/B2/B5 和 **B4-R：仅增加关联回放，使用相同保护规则**，检验 H1-R。第二阶段让 B3 与 B4-U 都使用相同回放范围，只改变独立／联合误差模型，检验 H1-U；再比较组合方案 B4。这样才能区分“回放有用”和“共享不确定性建模有用”。

| 测量 | 判读与分母 |
| --- | --- |
| 静态误删与可见变化召回 | 分别统计静态可见支持和可见移除事件；遮挡／视野外不充当已证实移除 |
| 身份与几何 | 对有物理 ID 的目标统计误合并、碎片与恢复；部分表面覆盖与可见投影精度分别报告 |
| 查询和坐标 | 固定语句及指定实例，报告回答覆盖、身份正确率和指定支持面距离；漏检、拒答均保留，不当作开放世界准确率 |
| 过期暴露 | 固定查询时序，累计错误旧目标仍被标为“有效”的时间，同时报告正确有效回答覆盖；事件完成和修正到达使用不同起点 |
| 恢复与成本 | 修正到结果更新／失效的时长、回放耗时、缓存命中和回退比例；来源缓存、检查点、RSS、显存分别计量 |

每台设备先做四事件各一次检查链路，再按验证会话调参，换布局作独立测试。以场景／会话为统计单位，不能把像素、点或三个随机种子充作独立样本。相同观测配对、同一电脑串行运行；固定资源限制，记录交换空间。评价距离和恢复阈值在验证阶段冻结，并保留敏感性曲线，不用更宽评分阈值制造提升。

查看测试结果前，还须冻结身份／坐标的最小有意义差异、参考测量容差和等效判据。“没有测到显著改善”不自动说明两方法等效；样本不足时结论写为不确定。现阶段未取得独立参考和会话数据，不预填置信区间、成功率或假设通过标记。

## 7. 什么结果会使我放弃或修改假设

| 观察结果 | 应作出的决定 |
| --- | --- |
| B2 已达到 B5 的身份和坐标质量，B4-R 无额外收益 | 否定该测试范围内“重算关联有必要”的主张 |
| B4-R 仅更接近 B5，独立真值质量无改善或更差 | 不宣称任务收益；检查作者核心本身的错误 |
| B1 达到相同风险—覆盖—延迟前沿 | 额外机制不值得当前成本，优先简单方案 |
| 改善来自拒答更多或永久保留旧物体 | 否定匹配覆盖／变化召回后的收益 |
| 只有已知协方差 oracle 有效，估计模型未校准或无收益 | 不接受 H1-U 的实际可用性主张 |
| 检查点或依赖闭包超预算，窗口外回退频繁 | 缩小适用范围，报告回退成本；不宣称普遍有界恢复 |
| 仅一个房间／布局有效 | 保留为局部现象，不提升为跨场景结论 |

当前可以提交的结论是：作者核心复现与受控探索使问题从泛泛的“抗位姿误差”收窄为“迟到修正后的关联恢复与目标有效性”，并给出了强对照及否定规则。H1-R、H1-U、设备实测和动态系统比较仍是后续工作。即使假设被否定，明确何时几何修正已经足够、何时有界缓存无法恢复，也是可复查的研究结果。
