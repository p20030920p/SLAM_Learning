# 自恢复主线（工作稿）

> **开放问题（定稿表述）**：在退化与大变动环境中，什么样的策略能够有效地让定位系统自恢复？
>
> 英文：*In degradation and large-change environments, what strategy effectively lets a localization system recover itself?*

**主线问题：退化和大变动场景下，定位系统的自恢复。**

定位系统在两类场景下失效，而现有方法对这两类失效的处理方式完全不同：

| 失效类型 | 触发原因 | 系统表现 | 现有主流处理 |
| --- | --- | --- | --- |
| **退化** | 几何/感知信息不足：长走廊、空旷区、动态遮挡、重复结构 | 观测对位姿的约束在某个方向上消失；似然面平坦或多峰 | 检测 + 抑制（冻结退化方向、降权、门控） |
| **大变动** | 先验地图与现状不一致：隔断改造、家具重排、门开合 | 观测与地图系统性冲突；位姿被拉走，或所有观测被当成外点 | 地图侧更新（重建/维护/多会话） |

**自恢复**在这里被定义为一个四段闭环，缺少任何一段都不算"自恢复"：

```text
检测（我不可信了吗，含误报代价）
  → 归因（是不可观测、地图过期，还是动态遮挡）
      → 恢复（选什么动作：不动 / 重定位 / 运动激励 / 改地图）
          → 确认（真的恢复了吗，多久、会不会复发）
```

## 为什么这个主线现在成立

三处断点，都有 2020—2026 年的文献支撑（逐条见 [SURVEY.zh-CN.md](SURVEY.zh-CN.md)）：

1. **检测侧的自指问题**：退化判据本身刚被证明不可靠——逐轴退化标签可能只是机体坐标系与度量选择的产物（[arXiv:2608.15532](https://arxiv.org/abs/2608.15532)），协方差正则化会掩盖退化（[arXiv:2608.19522](https://arxiv.org/abs/2608.19522)）。用这类信号无条件下发恢复动作，会带来未被测量的虚警代价。
2. **恢复侧基本空白**：绝大多数工作止于"抑制"（不让错误更新进来），而不是"恢复"（把已经错的位姿拉回来）。真正做恢复的只有两处极端：AMCL 内置的随机粒子注入（Sensor Resetting Localization, ICRA 2000，盲目、不报告成功）和稀疏距离采样先验（[arXiv:2607.17852](https://arxiv.org/abs/2607.17852)，有收敛保证，但前提是"变化的性质已被正确学到"）。
3. **评测侧没有标准**：经逐篇核验，**没有任何一篇同时报告**「检测混淆矩阵 + 恢复成功率 + 恢复时延 + 复发率 + 误报代价」。现有评价几乎都是最终 ATE/RMSE。

因此本主线的可辩护贡献不是"再做一个更好的定位器"，而是：

> 把 **检测 → 归因 → 恢复 → 确认** 做成一个可测的闭环，并给出"恢复能力"的信息下界（什么条件下根本不可能恢复）。

## 与旧方向的关系（为什么要砍掉语义建图）

- 旧库把"动态环境鲁棒定位"与"语义建图/视觉定位"糅在一起，两边的评价指标、真值形式和系统接口都不同，导致每条线都讲不透。新库只保留第一条。
- 保留的 DUFOMap / BeautyMap 属于**地图侧抑制**（离线清除动态点），在新主线里的角色是：对照基线 + 一个可复用的判据来源（"地图未解释的观测"）。
- **新增的桥接点**：动态遮挡与结构改动在单帧观测上是同一件事（地图未解释的观测），差别只在时间统计（短暂 vs 持久、换位置 vs 同位置）。这条差别正是把"动态点过滤"升级为"地图过期检测"的接口。

## 现有实验平台（要复用的部分）

`results/localization/static-dynamic/` —— Gazebo 中的 2D 激光 / RGB-D 建图 + AMCL 定位回放：纯静态场景、三个移动箱子的动态场景、干净地图 + 动态测试的对照，42 次 AMCL 回放、位置 RMSE 表与误差曲线 GIF。

这套平台对自恢复主线的价值与缺口：

| 项目 | 现状 | 对自恢复主线的意义 |
| --- | --- | --- |
| 场景可控性 | Gazebo 世界、地图、测试轨迹都可脚本化重建 | 可以造"建图后世界被改"的大变动场景（**这是现有其他数据集给不了的**） |
| 真值 | 全轨迹真值 + 移动物体真值位置 | 恢复率/时延/复发率都可以精确打分 |
| 对照设计 | 已有"干净地图 + 动态测试"这一关键对照 | 可把失效原因从"地图污染"里分离出来 |
| **缺口 1** | 回放里**没有记录**恢复相关内部量（w_fast / w_slow、随机注入事件、粒子云统计） | 恢复类指标现在算不出来，需先加一次记录改造（不改场景） |
| **缺口 2** | 没有"结构被永久改变"的场景档位 | 需要新增：建图后改世界再定位（改动比例 k 档） |
| **缺口 3** | 没有几何退化档位（长走廊/空旷区） | 需要新增一档走廊场景 |
| **缺口 4** | AMCL 无因子图后端 | 撤销/回滚类方法（RRR、GNC、DCS…）需要另建离线 2D 位姿图才能对照 |

此外有一条**真实数据捷径**：LILocBench（IROS 2025）就是 2D 激光 + 轮式里程计 + RGB-D 的室内长期数据集，含 static / dynamics / long-term changes / changes+dynamics 四类序列，公开真值在**单一全局坐标系**内（无需轨迹对齐），并附带官方 occupancy map 和评测代码。无相机的 bag 很小（dynamics_0 约 38 MB，lt_changes_4 约 240 MB），AMCL 可以直接消费。详见 [FEASIBILITY.zh-CN.md](FEASIBILITY.zh-CN.md)。
