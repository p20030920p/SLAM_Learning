# 鲁棒定位与自恢复汇报稿

下午好，我是朱子霖。我希望研究的方向是 **Robust localization and SLAM in dynamic environments，也就是动态环境中的鲁棒定位与 SLAM**。

这几天，我重新整理了仓库，也修正了此前的研究思路。我最初同时关注动态环境建图和语义建图，并尝试把四篇工作的结果放在同一张定位误差表里。但后来发现，这种比较回答的问题，比我原先以为的要窄。

DUFOMap 和 BeautyMap 主要关心动态点是否去除、静态结构是否保留。ConceptGraphs 和 HOV-SG 更关注对象、语义表示及其下游任务。我把后两者转成几何投影，再交给 AMCL 定位，确实可以观察这些投影地图对定位的影响，却不能据此评价四篇论文各自目标的完成程度。

因此，我现在把精力集中在一个问题上：**在退化与大变动环境中，什么样的策略能够有效地让定位系统自恢复？**

这个问题来自我以前参与的点云去雪和机器人竞赛经历。在点云处理中，我接触过局部邻域统计、点密度和反射强度等线索。同一套过滤规则换了传感器或场景，效果可能变化；去掉噪声的同时，也可能误删定位需要的结构。

在机器人竞赛中，我接触过 Cartographer 或 Gmapping 建图、A* 全局规划和 DWA 局部规划组成的导航系统。实际部署时，TF、时间同步、里程计误差和环境变化都会影响表现。这让我开始关心：系统定位出错后，能否发现问题，并在没有人工重新指定正确位置的情况下恢复？工程配置问题仍需要先检查，不能全归因于算法。

我对 SLAM 的理解是：利用传感器观测，在估计自身运动的同时构建地图。前端处理观测和匹配，后端优化位姿或约束，回环帮助减少累计漂移。我的当前实验首先研究的是已有地图上的定位，因此 AMCL 是状态估计器，并没有运行完整的 SLAM 后端。

我想把“自恢复”拆成几个可以观察的环节：发现定位可能不可信，生成新的位姿候选，再用后续观测确认是否恢复。失效原因可能是短暂遮挡、几何约束不足，也可能是地图与世界持续不一致；如果暂时不能区分原因，我希望系统能够保留“不确定”的状态，而不是过早宣布自己恢复了。

目前，我保留了 DUFOMap 和 BeautyMap 的地图清理复现，也有 IR-MCL 的公开序列运行结果。AdaM-MCL 的自建数据演示使用了缩短的训练预算，十次重复尚未达到记录中的持续收敛判据。这些结果帮助我理解地图质量、观测模型和训练条件，但还不能证明新的自恢复策略有效。实时分屏录制仍有渲染问题，我不会把未通过检查的画面当作成功演示。

首轮实验我希望做得小一些：固定二维激光、里程计、地图和计算预算，对比没有额外恢复的 AMCL、显式开启随机注入的 AMCL、简单阈值触发重定位，以及加入时序触发和持续确认的策略。先让这些方法收到同一份录制输入，分开改变动态遮挡、地图结构变化和传感器条件。

评价上，除了位置和角度误差，我还想记录恢复成功的比例、恢复需要多久、正常运行时是否误触发，以及宣布恢复之后是否再次失效。真值只用于评分，不能用来触发恢复。若观测本身不能区分位置，重定位也可能无效，这时应该报告不可用，而不是承诺一定能恢复。

我现在还没有证明这套策略优于现有方法，也没有把它当作已经确定的新贡献。今天希望和老师讨论三个取舍：首轮是否适合聚焦触发和确认，哪些失败场景最有研究价值，以及简单基线做到什么程度后，再引入学习模型或地图更新。

无论最终是否进入实验室，我都希望通过这次交流，把问题定义和实验方法学得更扎实。谢谢老师。
