## 1. 第一轮：传感器本身，暂不手持走动

各固定 60 秒。相机对准约 1–3 m 的哑光有纹理平面/墙角；L2 平放，视野有不同方向墙面和家具。每次记下“确实固定”、距离、照明、投射器、线缆和场景照片。

| 检查 | 应看到的画面 | 项目初期目标与解释 |
| --- | --- | --- |
| 相机硬件四路 | RGB 清楚；左右 IR 视差一致；深度边缘大致稳定 | 原始独立采集稳态每路 29–31 fps；序号缺失 <1%，时间不倒退，稳态无 >100 ms 停顿。启动前 2 秒另报，不能静默丢掉 |
| 相机深度有效性 | 选定哑光平面中央 ROI 有深度 | ROI 有效比例 >90%；2 m 固定平面 ROI 中位深度时间标准差 <10 mm。全画面有效比例受遮挡影响，不代替 ROI 指标 |
| 尺量测距 | 卷尺独立量 1、2、3 m，同一平面取 ROI 中位值 | 偏差 <max(3 cm, 距离×2%)，注明光心基准、尺量误差和 ROI。无参考时只能报读数，不能报准确率 |
| L2 收流 | 多方向墙面/地面几何稳定，点云分组刷新 | CRC 理想为 0，拒绝及序号缺失各 <0.1%；无时间倒退；约 216 线包/s、250 IMU 包/s 是当前实测参考 |
| L2 聚合 | 50 线组约 4.3 Hz，逐组扫描覆盖变化 | 线包率、软件组频率、电机转速分开报告；当前点云不做去畸变，快动会重影 |
| IMU 和时间 | 固定 IMU 曲线无持续偏转，设备时间持续推进 | 单位/轴核实后重力模长接近当地重力，静止角速度均值先以 <0.05 rad/s 排查；原始数值未核实前不硬套此单位 |

硬件原始采集可使用现有 `capture_pair.ps1`（同时录两台），或相机固定录像入口，见[相机指南](CAMERA_GUIDE.zh-CN.md)。新实时入口按配置抽样并做 SDK 对齐，`ros_input_hz` 是算法实际输入率；`-FPS 10` 是上限，低于上限不是原始 USB 丢帧的直接证据。

时间单独验：拟合 `host_elapsed = a × device_elapsed + b`，保留原始值、漂移、分段残差；当前 L2 `a≈2` 的原因必须解释。进入 LIO/跨设备融合前，先以比例差 <1000 ppm、受控同步残差 p95 <5 ms 为目标，并报告参考方法；USB 到达抖动不能当硬件同步精度。不要用简单缩放覆盖原始时间。

## 2. 第二轮：固定时算法是否产生假运动

用指南中的 `-SessionType stationary -Seconds 60 -Record`。相机 stereo→RGB-D；雷达 ICP→KISS。算法比较尽量重放同一原始录制；实时分别采集只能作为不同会话，不能称完全相同输入的公平对照。

**应看到：** 轨迹贴近原点，静态墙面位置不持续漂移，状态不反复 LOST。短暂初始化可以出现；固定时不断绕圈、轨迹渐渐爬走，即便有所有位姿输出也判失败。

**目标：** 最大平移偏离 <5 cm、最大转角 <2°；稳态位姿输出覆盖 >95%，正常固定 lost <5%。覆盖包含失败位姿时必须结合 lost 和有效位姿数，不能把它当跟踪可用率。KISS 没有此 API 的 lost，填 null，主要依据受控物理固定偏离。

`translation_excursion_max_m` 是相对首个有效位姿的最大偏离，`estimated_path_length_m` 是估计轨迹累积长度；抖动会让后者很大。移动时这两个量不叫静止误差。原始输入零个、算法零位姿会让入口报错；有输出但精度失败会保留数值，不替你判成通过。

## 3. 第三轮：拿着相机/雷达按这个顺序移动

相机和雷达分别做；没有刚性安装和标定时不要拿两台一起晃动。开始前地面贴起终点胶带，独立尺量 2 m，设朝向标记。

| 顺序 | 你怎样做 | 正常视频效果 | 指标与初期目标 |
| --- | --- | --- | --- |
| 1 | 起点固定 5 s，沿尺量直线慢移 2 m，终点固定 5 s；回起点重做，共 3 次 | 轨迹连续、方向与物理动作对应；相机画面有充分重叠 | 终点位移长度误差 <5%（2 m 时 <10 cm），同时报横向偏差和尺量不确定性 |
| 2 | 固定同一位置，慢转约 90°再回原朝向，避免大平移 | 主体以旋转响应；地图不随转动严重扭曲 | 朝向恢复误差先要求 <5°；报告实际转动参考，不把手腕绕圈当纯旋转真值 |
| 3 | 慢走 5–10 m 小闭环，回同一位置和朝向，起止固定 | 里程计可能有累积漂移；rgbd-slam 成功回环时全局地图可调整 | 终点偏差先要求 <20 cm、朝向 <5°；回环前/后分别报，不期待 ICP/KISS 自动全局闭合 |
| 4 | 单独做白墙、亮屏、遮挡、快速转动对照 | LOST 或重影可能发生；恢复过程可见 | 报丢失次数、最长持续、恢复时间和错误恢复，不和正常慢走混为一个均值 |

正常慢走的**可用跟踪比例 >95%**（既有匹配输出且未 lost，分母为输入观测数）；初始化单独报告。计算 p95 应小于实际输入周期，排队延迟不随时间增长。当前 JSON 的 `odometry_compute_ms` 是原生节点报告的算法计算时间，不含完整 Windows→WSL→渲染延迟；端到端需另用受控动作/共同计时实验测量。

相机 stereo 增加 emitter 开/关同路线对照；RGB-D 首先改善光照、避开近物/亮屏。L2 增加 18/50 线聚合对照，固定其余参数；在时间和 IMU 条件成立后才比较去畸变/LIO。

**ATE/RPE 暂留空。** 只有具备独立参考轨迹且报告精度、时间关联、SE(3) 对齐方式和匹配覆盖后才计算。卷尺只支持距离/终点误差；另一套 SLAM、算法回环和 IMU 不能当轨迹真值。具备参考后，小房间可先以 ATE RMSE <10 cm、每 1 m 相对平移误差 <5 cm 为目标，连同转角和失败会话一起报。

## 4. 第四轮：接主分支地图与语义算法

执行细节与接口命令见[主分支测试和合入指南](MAIN_INTEGRATION.zh-CN.md)。先使用确实固定的会话，单位位姿假设有依据；移动会话需已验收的位姿来源，不能把失败雷达轨迹直接作为地图真值。

| 算法 | 视频应呈现的内容 | 什么才算向目标推进 |
| --- | --- | --- |
| DUFOMap | 原始累积云、保留云、删除部分同时展示；移动人/箱子的拖影减少 | 有标签后统计静态保留 SA、动态清除 DA、静态误删、延迟；有限 PCD/点数比不等于准确率 |
| BeautyMap | 同输入同位姿，清理前后对照，静态墙和细结构尽量保留 | 原小地图边界错误先在独立适配副本修复并回归原 KITTI；局部扩域对照不是主分支已修好 |
| ConceptGraphs | 对齐 RGB-D、掩码、对象点云/ID、文本查询候选 | 同一实物身份稳定；量身份碎片、错误合并、查询准确率、目标坐标误差；高亮只是候选 |
| HOV-SG 当前核心 | 分段/特征地图与查询候选 | 量分段稳定、覆盖、查询效果、内存/时延；当前核心不等于完整楼层导航系统 |

四类受控事件：静止、遮挡但未移动、移除并让旧位置可见、沿胶带移动 30 cm。每类 80 秒：0–20 固定，20–25 动作，25–60 保持，60–80 恢复；记录实际完成时刻和物体 ID。验证集每类至少 3 次，冻结参数后换布局，正式测试每类至少 5 次。一次会话是统计单位，不把点数当独立实验数。

初期目标：可见静态支持误删 <5%，可见移除事件召回 >80%，独立表面锚点坐标误差 <10 cm；记录置信区间与参考误差。遮挡不误删、移除可检测是测试要求，不能假定原算法保证实现。先证明输入适配正确，再评价原算法能力和扩展方案。

随后才做主分支迟到位姿修正实验：固定 40 个观测，按原设计注入 10 cm 漂移并分时交付历史修正，对比原核心、几何修正、全量重建；关联重放等尚未实现的方案不能提前写成有效。

## 5. 每个会话交付这些材料

- 原始录制/哈希、设备/版本、SDK/算法提交、完整命令与配置、是否固定/移动、时间/坐标/单位约定。
- 完整 LIVE 录屏，或明确标注的 OFFLINE ALGORITHM 视频；同时看到真实输入、状态、轨迹/地图和动作时刻。纯点云旋转预览不叫定位视频。
- 输入数、匹配位姿数、有效比例、lost/不可用项、最大固定偏离或移动终点误差、计算/排队指标；无真值的 ATE/RPE 留空。
- 标注与分母、失败日志、未通过原因、待修复项；参数冻结前后的验证集/测试集分开。

合入顺序：筛选硬件模块→从 main 建独立集成工作树→原 KITTI/Replica 回归与实物回归→审查 PR→之后由用户决定。当前 orphan 分支没有共同祖先，不能把整套个人历史直接合进 main。**现在不合并。**
