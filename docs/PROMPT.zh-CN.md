# 适用于方向 1–2 的研究提示词

我希望聚焦「动态环境中的鲁棒定位与 SLAM」以及「语义建图、视觉定位与导航」。我不希望得到按论文罗列优缺点的综述，而希望从系统结构上找出几篇近期工作共同依赖的假设：它一旦不成立，会使哪类任务天然不可辨识，或使方法即便更换网络、扩大训练集、调整阈值也难以可靠完成？

请对 DUFOMap、BeautyMap、ConceptGraphs、HOV-SG、Khronos、DovSG，以及最新可查证的时空语义地图工作做这样的分析。沿「位姿估计 → 空间对应 → 动态／可见性判断 → 对象与语义融合 → 地图更新 → 定位或导航查询」追踪信息流，说明每个决策依赖什么输入、哪些误差由多个对象或多次观测共享、后续模块是否还能修正已经提交的错误。

我特别关心：定位漂移被误认为对象移动或消失；遮挡被误认为不存在；重复但相关的观测被当作独立证据，令地图越来越自信地保留或删除错误对象；错误地图又影响后续定位。不要先假定这些现象已经发生，也不要说所有方法都忽略动态性。说明哪些方法已经处理可见性、长期记忆或联合优化，并将其作为反例来缩小问题。

给出原文章节、公式和作者代码位置，区分「论文明确陈述」「结构推导的风险」「实际观测」「待验证假设」。用 3–5 年内几篇核心论文形成可核查论证，最新预印本作补充，不能凭项目介绍声称代码可复现。

提出可证伪假设和最小实验：分别控制位姿误差大小与相关性、锚点比例、对象运动比例、遮挡和回环修正延迟；保留作者方法及阈值／容差基线；比较误删、变化检出、对象身份、目标位置误差和校准。延迟更新或拒答的方法必须匹配覆盖率和更新延迟。合成机制实验不能冒充完整 SLAM、语义建图或导航复现，负面结果必须保留。

交付可审查的 GitHub 仓库：研究问题、来源对照、固定版本与数据校验、运行日志和原始指标、图表代码、失败记录及边界。不要用“完成”标签代替证据，也不要把本地历史成绩当成论文基线。
