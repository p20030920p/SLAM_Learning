# 使用 D435 和 Unitree L2 的居家验证设计

[English](REAL_WORLD.md) | 中文

本研究协议尚未完成；基础收流与原生加载检查见[实物分支](https://github.com/p20030920p/SLAM_Learning/tree/Personal-Learning-Physical)。使用 D435（SDK 实测，无 IMU）、L2、三脚架和尺量事件检验地图与目标有效性，不需要移动机器人。

## 1. 要区分的三个问题

| 问题 | 干预 | 主要判据 |
| --- | --- | --- |
| 可见性是否被误当作变化 | 传感器固定，目标静止／遮挡／移除／移动 | 静态误删、可见移除召回、目标旧坐标过期时长 |
| 位姿修正是否足以恢复目标 | 同一批原始观测与特征，修改历史位姿后固定／重新计算关联 | 表面覆盖、身份碎片、目标坐标误差与恢复时间 |
| 有界 H1 是否值得额外成本 | 独立方差保护与共享位姿保护，匹配召回／覆盖／延迟 | 风险前沿、峰值内存、回放时间与过期结果暴露 |

实物分支已有基础采集、导出与原生加载检查；受控事件标注、语义执行和候选恢复仍待完成。图像或点云可见只证明采集／查看链路，不等于 H1 得到验证。

## 2. 房间与独立参考

背景至少包含墙、地面和另一方向的平面，尽量覆盖多个方向；需要估计完整位姿时使用独立测量的多标记板或充分可观测的背景。单个平面不能约束所有自由度。将标记固定在背景，移动物体不贴定位锚点。

固定传感器，初始目标距其约 1.5–3 m，以实际深度有效率和 L2 回波密度为准。给椅子和两个相似箱子分配物理 ID，在地上贴初始和 30 cm 移动位置，记录尺量不确定性。另一个手机固定拍到物体、传感器和会话编号。

算法可见锚点属于辅助输入，必须对所有相应基线相同；评价专用标记不能泄漏到算法输入。D435 实测无 IMU；IMU 也不能作为位置真值。固定传感器采用单位相对位姿；原点与轴在每个会话开始记录。

## 3. A 固定传感器事件

每台传感器分别采集四种事件。每段 80 秒：0–20 秒静止基线，20–25 秒执行事件，25–60 秒保持，60–80 秒恢复和静止。记录实际事件时间，搬动过程单独标为过渡，不算已经完成的状态。

| 事件 | 动作 | 正确判断需要什么 |
| --- | --- | --- |
| 静止 | 全程不动 | 不应凭观测抖动删除或分裂目标 |
| 遮挡 | 挡板遮住椅子，椅子不动 | 隐藏／未知不等于消失；移开挡板后恢复同一物理 ID |
| 移除 | 搬走椅子，原空间和背景继续可见 | 必须有射线／深度证据到达原空间，才评价可见移除召回 |
| 移动 | 沿胶带移动椅子 30 cm | 新位置有效，旧坐标应过期；不能用“永久保留”换低误删 |

另加视野外与“大多数相似箱子同向移动、稳定背景被挡住”的失败对照。看不到旧空间时不算可见移除；没有稳定锚点时不要求系统凭空区分相机漂移与物体运动。

先各做一段四事件演示（每台 5 分 20 秒），只用于检查链路。正式探索建议每事件 3 次验证会话，冻结后换布局做 5 次测试会话；每台共 32 段、42 分 40 秒原始数据。这个规模不保证统计功效。测试前不查看结果，按会话而非像素或随机种子统计。

## 4. B 同观测的迟到位姿修正

先从固定设备录制抽取 40 个有时间戳观测，保持图像、深度、标定、掩码和逐掩码特征不变。以单位位姿为参考，0–7 观测无误差；8–15 观测注入世界 x 方向 0→10 cm 的线性偏差，其余无误差。这是确定性的恢复压力测试，不是定位噪声模型；报告实际 RMS、极值和时序，不使用排序误差来声称隔离相关性。

在第 16／24／36 观测分别交付同一组历史修正，恢复 8–15 的参考位姿。固定顺序为先接收修正、后处理当前新观测，缓存此前最近 16 个已处理观测：交付时缓存分别为 0–15、8–23、20–35；前两种来源在窗口内，最后一种在窗口外。

24 是恰好仍保留第 8 帧的边界，处理新帧后再修正会改变结果，必须记录实际顺序。窗口外须全量重建或明确不可恢复。

事件条件与修正延迟交叉；先固定身份的静止片段调试，再冻结测试条件。旋转与手持估计位姿是后续单独因素。

| 比较条件 | 固定或改变什么 |
| --- | --- |
| B0 原核心 | 保持原关联／融合与原历史决策，作为未恢复对照 |
| B1 简单保护 | 验证集选择阈值／可见性规则；保留 ConceptGraphs 阈值 1.0 等竞争工作点 |
| B2 修正几何但冻结关联 | 用同一缓存原观测重新投影，保持修正前的对象归属；区分坐标修正与关联恢复收益 |
| B3 独立方差保护 | 相同来源缓存、预算与提交策略，按独立方差决定暂定／提交 |
| B4 候选共享位姿保护 | 只增加共享位姿处理与受影响关联回放；不能同时获得更强前端或更多标注 |
| B5 oracle 全量回放 | 用修正后的完整历史从头重建，作为正确性参考；时间和内存照实报告 |

先执行 B0／B1／B2／B5，并增加只改变关联回放、保护规则相同的 B4-R，确认回放是否比只改几何有必要。第二阶段 B3 与 B4-U 使用相同回放，只改变独立／联合误差模型，避免混淆两项机制；不确定性估计器须明确实现并校准，已知注入误差／协方差属于 oracle，单独列出。

B5 是同核心在修正输入上的参考，仍须对独立真值评价，不当作无误答案。完整定义见[已填研究稿](../notes/OPEN_QUESTION_AND_HYPOTHESIS.zh-CN.md)。

共享版本／来源记录不是已证明的新颖算法。

## 5. C 手持重访与双设备扩展

固定设备测试通过后，分别手持慢走 1–2 分钟，重访同一场景，起止静止。估计里程计与独立背景／标记参考分开，记录重投影残差、深度误差和参考不确定性。L2 保存逐点时间与 ring，扫描运动需去畸变，不能全部归因于场景变化。

两设备先各自测试。只有刚性安装、外参标定、时间偏移及漂移量测、另一设备开／关干扰对照完成后，才开展共同几何实验。USB／网络时间戳不自动构成共享时钟和融合系统。

## 6. 测量与否定规则

| 指标 | 定义与报告方式 |
| --- | --- |
| 静态误删／真实移除召回 | 独立标注的静态可见支持误删比例／可见移除事件检测比例；事件和点级分母分开 |
| 覆盖与身份 | 已标可见表面 10 cm 内覆盖；匹配表面可见投影精度至少 50%、覆盖至少 20% 才算恢复；记录一个物理 ID 对应的片段数 |
| 目标坐标误差 | 对独立测量的指定表面锚点报告距离与参考误差；不声称完整物体中心或导航误差 |
| 过期与延迟 | 实际事件完成到旧坐标失效的时间、修正送达到查询更新的时间；有效／暂定／过期／不可恢复均记录 |
| 计算与预算 | 同一电脑串行执行；16 观测／512 MiB 仅是候选来源缓存预算，进程 RSS、峰值显存与回放耗时另外实测 |

先在验证会话选择工作点，测试时报告完整风险—覆盖—延迟曲线，并匹配变化召回。若简单保护达到同样前沿、B2 已解释全部恢复、估计不确定性未校准，或少删除仅靠更多过期目标，应否定相应 H1 收益。查询拒答计入覆盖损失，窗口外失败保留。

## 7. 采集与视频证据

D435 使用官方 RealSense Viewer 录原始 RGB／深度，并保存内外参、深度标尺、SDK／固件版本和文件哈希；此设备没有 IMU 流。官方新文档使用 `.db3`，旧版本使用 `.bag`，按实际版本选择并回放检查；格式名不能证明 IMU 完整。[官方录制与回放](https://github.com/realsenseai/librealsense/blob/master/doc/record-and-playback.md)。

L2 使用固定提交的 SDK2／ROS2 包，保存 PointCloud2 全字段和 IMU、逐点 time／ring、实际话题及 TF；官方默认话题是 `unilidar/cloud`、`unilidar/imu`，雷达坐标系为 `unilidar_lidar`。官方列出的 ROS2 验证环境是 Foxy，本机 Humble 硬件连通性需另验。

[官方 SDK2](https://github.com/unitreerobotics/unilidar_sdk2)。

每段保留原始文件、`capture.json`、标定、`events.csv`、对象 ID／可见性标注、参考测量、日志、屏幕视频和手机事件视频。录屏主画面是 RGB-D／三维点云及地图／目标结果，终端用于显示命令和退出码。算法运行与离线结果查看分开标注。主分支只发布经核查的轻量证据及短片；大文件留本地。
