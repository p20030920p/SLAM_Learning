# D435i 与宇树 L2 的实物实验

[English](REAL_WORLD.md) | 中文

**状态：拟定协议，尚无实物实验成绩。** 固定传感器的变化测试和手持建图不需要移动机器人。现有设备是 D435i RGB-D／IMU 和宇树 L2 LiDAR／IMU。先分别测试；双传感器实验必须有刚性支架、外参标定和实测时钟对齐。

## 可以测什么

| 设备／摆放 | 能回答的问题 | 不能证明的结果 |
| --- | --- | --- |
| 固定 D435i，人工移动物体 | 遮挡与移除、语义关联、当前目标坐标 | 机器人导航成功率、绝对 SLAM ATE |
| 固定 L2，人工移动物体 | 自由／占据证据、静态损失、动态清除、稀疏可见性 | 没有新标注就获得 KITTI 等价成绩 |
| D435i 或 L2 固定在手柄上手持 | 重访一致性、漂移影响、修正后恢复 | 仅由 IMU 积分获得准确轨迹真值 |
| 两者固定在同一板上 | 更宽的稳定背景是否帮助区分相机误差与物体变化 | 有两个 IMU 就自动完成融合 |

[D435i IMU 标定指南](https://www.intel.com/content/dam/support/us/en/documents/emerging-technologies/intel-realsense-technology/RealSense_Depth_D435i_IMU_Calib.pdf)与 [L2 SDK](https://github.com/unitreerobotics/unilidar_sdk2)提供接口依据。L2 SDK 暴露点云、IMU、逐点时间和 ring，采集时保留以便去畸变。各设备带时间戳不等于共享时钟。

## 准备一个房间

在能看到墙面和地面的房间摆桌子、椅子、箱子、挡板及两个相似物体。用胶带标记位置，用尺测距离。初始可安排在 1.5–3 m，再检查深度有效率和 LiDAR 点密度；这是测试布置，不是设备量程指标。

传感器放稳固三脚架；标记板固定在背景，不贴移动目标。另用手机拍传感器、物体和会话编号，证明事件顺序，不能当毫米级真值。算法能看到的标记属于辅助基线；只用于评价的标记必须从算法输入遮掉，或用独立视角处理。

先录 30 秒静止场景，检查掉帧、深度尺度、内参、畸变、单位、坐标轴、IMU 重力方向。另一设备分别开／关再录，排查深度或回波变化，记录无效深度比例、平面拟合残差。确认原始文件能回放，再移动物体。

## 采集路径

D435i 可用 [librealsense 原生录制](https://github.com/realsenseai/librealsense/blob/master/doc/record-and-playback.md)，将原始流保存为 `.bag`。仓库提供便捷入口：

```bash
python scripts/capture_realsense.py --session A-static-01 --seconds 120
```

在安装官方 `pyrealsense2`、能直接访问设备的环境执行。请求 RGB／深度 640×480、30 Hz 和设备默认 IMU 配置，记录标定与 bag 哈希。脚本已检查语法／帮助，**本次尚未连接硬件验证**。SDK 接收样本也不能证明 bag 中完整 IMU 频率。

WSL 的 USB 透传和以太网访问是独立配置任务；D435i 先在 Windows 原生采集较直接。不要自动改主机网络或雷达工作模式。L2 先核查官方 SDK 示例，用受支持的 C++ 或 ROS 接口保存点云／IMU。SDK 发布的 ROS2 示例验证平台是 Foxy，不能据此声称任意 Ubuntu／ROS 组合已通过。

已有经过验证的 ROS2 环境时，先查实际话题：

```bash
ros2 topic list -t
ros2 topic hz /unilidar/cloud
ros2 topic hz /unilidar/imu
ros2 bag record -o L2-A-static-01 /unilidar/cloud /unilidar/imu /tf /tf_static
```

这是 SDK 默认雷达话题；相机话题会随封装版本变化。录 RGB、适当的原始／对齐深度、camera_info、两种运动流。RealSense 原生 bag 不能当 ROS2 bag 用。每个会话固定驱动提交、固件、配置和实际话题列表。

## A：固定传感器，四种可区分事件

两个传感器分别采集。每次先录 20 秒不变参考，再执行一个事件，随后观察至少 20 秒。每个事件前恢复原场景。

| 事件 | 操作 | 应区分的语义 |
| --- | --- | --- |
| 静止控制 | 什么都不动 | 静态误删和身份碎片化应低 |
| 遮挡 | 挡板遮住椅子，椅子不移动 | 未知／隐藏，不能证明移除 |
| 移除且可见 | 搬走椅子，继续看到原占据空间／背景 | 有可见性证据的实际消失 |
| 移动 | 沿胶带将椅子平移，例如尺量 0.3 m | 新当前坐标，旧坐标过期 |

再单独录“目标在相机视野外”。L2 和相机覆盖不同，只在各自可观测区域判断消失。射线没到达原占据空间，不能证明物体不存在。

先对固定设备用单位位姿处理，重复静态观测作为负对照。LiDAR 适配器输入只给 XYZ 和真实传感器原点，不给语义真值；归档保留逐点时间／ring，评价标签另做。语义适配器保留原始图像／深度、标定内参、逐帧位姿，掩码与特征来自原前端。

## B：手持重访与独立参考

慢走 1–2 分钟闭环，回到起点胶带，重新观察原场景。设备固定在刚性手柄，保留静态背景，起止静止。LiDAR／IMU 里程计或 RGB-D 里程计给出的是**估计位姿**；D435i 不是跟踪相机，任何一套 IMU 单独积分都会漂移。

用多块背景标记／平面检查相对位姿一致性。标定后的标记 PnP 仍是有噪声参考，不是动捕真值，记录重投影误差和视角。比较固定 A、手持 B 及同一录制中的受控位姿扰动。L2 需保留扫描内运动／时间以去畸变，不能把采集畸变全部归为场景运动。

## C：假设的配对实验

使用**同一批录制帧**，固定掩码／特征，分别重放参考、估计、独立扰动和连续相关位姿。拟定平移 RMS 0／1／3／10 cm，旋转 RMS 0／0.3／1／3 度。固定地图规范，并在第一帧归一化后核查实际 RMS。这些是草案档位，只能在验证会话改，随后冻结。

比较普通阈值扫描、可见性保护、独立位姿不确定性、候选共享变量／暂定更新旁路。已知注入协方差只作 oracle 上界诊断，还要比较实际估计版本。保存完整风险—覆盖率—延迟曲线，同时匹配变化召回；旁路缓存和重放成本算入预算。

加入失败条件：遮住稳定标记，让大多数可见相似箱子同向移动。增加观测次数或中位数修正都不能创造缺失锚点。恢复标记后重做，区分信息不足与算法缺陷。

## 标注、重复与交付

采集前分配物理对象 ID，记录初末位置、事件区间、可见／遮挡／视野外状态和尺量不确定性。标一小批逐帧掩码或三维框；只有事件时间不能计算逐点 SA／DA。尺量位置及误差可以支持目标坐标评价，不能自动支持厘米以下精度宣称。

每种事件先做 5 次独立验证会话，协议冻结后换布局／房间再做 5 次测试。这是建议最低规模，不保证统计功效；按会话计算区间，不能把每个深度像素当独立样本，也不能只挑一段干净视频。

报告静态损失、变化召回、身份切换／碎片化、目标坐标误差、查询覆盖率、过期持续时间、更新延迟和资源；没有机器人就不报告导航成功率。失败采集和多数同向运动失败也保留。

每个会话保留 `capture.json`、标定、原始文件哈希、带坐标约定的位姿、标注、原日志、指标、手机视频和固定视角结果回放。主页展示**真实输入＋地图决策＋标注／事件标签**，注明会话编号、单位、提供／估计位姿与播放范围。采集完成之前，保持明确的计划状态，不放编造照片和分数。
