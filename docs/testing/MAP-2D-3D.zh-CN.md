# 为什么清理了地图，定位误差仍没有明显降低？

本轮实测不支持“换成三维就一定有效”。DUFOMap、BeautyMap原本就处理三维点云；此前只是在清理后投影成二维图，再交给AMCL。现在保留完整三维地图，改由同一个原库GICP分别定位，前三个场景仍未看到清理带来的定位改善，走廊则出现发散和有效输出缺失。地图清理质量与定位误差必须分开看。

## 本轮实际做了什么

同样的四种Gazebo世界、机器人、巡航路线和初值偏移。静态、动态、持久变化录制90仿真秒；走廊录制120仿真秒。Raw／DUFOMap／BeautyMap只改变先验地图。二维使用AMCL，三维使用固定参数的原库GICP、16线三维雷达和轮式里程计；三维观测为720×16、垂直±15°、12m量程。三维走廊也限制为240°、72个水平方向、3.5m，50秒后恢复，并保留完整观测控制组。

建图A仍使用相同的给定传感器位姿融合、清理点云，符合两种清理器的输入形式；这不是新增完整三维SLAM。新仿真B的定位器不读取真值，真值只供独立评分。三维地图直接来自各方法的`points.npy`，没有再用二维投影估计位姿，三组定位器的全局TF广播关闭，RViz只接收各自隔离的显示TF。

二维报XY RMSE，三维报XYZ RMSE，另保存完整旋转误差。均使用所有已发布且与真值相差不超过0.05仿真秒的原生输出，不进行空间拟合。GICP首次输出已经经过配准，未发布的初始信念和失去输出的时段没有被补成零误差。两维度更换了传感器、定位器及输出频率，绝对数值不能证明“三维本身带来多少收益”。当前并行运行共享输入源，启动及实际消费的扫描历史仍可能不同；每条件一轮，也不能据此作算法排名。

同一动态B中的静态地图控制组，Raw／DUFOMap二维图像素相同，却分别得到7.70／7.93cm，也暴露了流程波动。恢复标准沿用平面巡航的XY<0.1m、|yaw|<5°持续5秒且至少8次更新；三维XYZ及完整旋转误差另存，未宣称完整六自由度恢复成功。

走廊的三维Raw、DUFOMap地图字节相同，结果却不同，说明不能把该差异归因于清理器。恢复发生在t=62.1s；Raw、DUFOMap、BeautyMap最后有效输出分别在63.5／76.4／119.3s，样本数530／599／655。Raw不足以评价持续恢复；另外两组未达到5秒持续收敛标准。三个完整观测控制组也在约23s停止产生有效输出，因此问题不止是观测限制造成的。**这些RMSE只覆盖已发布输出，不能掩盖输出中断，更不能比较优劣。**

## 地图是否真的被清理了？

动态建图A重新记录了实际运动箱体的模型、链接位姿和父子关系。按每帧时间戳将世界点变换到箱体坐标系，以2cm表面容差标注动态返回，2–5cm边界带及近距离自返回不评分。共685047点：677851静态、7076动态、120不评分；动态仅约1.03%。动态表面距离P95为0.74cm。以下都在相同的60帧输入点上评分，未用删点数代替准确率。

[新建图A的真实雷达输入采集录像](../../results/reference/robot-3d-dynamic-mapping/execution.mp4)中保留二维slam_toolbox显示及独立三维扫描，之后才离线运行三维清理器。

| 方法 | 静态点保留 | 动态点去除 |
| --- | --- | --- |
| Raw | 100% | 0% |
| DUFOMap | 99.998% | 46.59% |
| BeautyMap | 81.15% | 74.36% |

DUFOMap有真实清理效果，且几乎不损失静态点。BeautyMap删动态更多，但同时误删127758个静态点；这些误删点几乎都不属于z<0.12m地面带，不能把差异简单解释成“去掉了地面”。[可重算的几何标签、保留掩码、原生输出哈希与参数](../../results/reference/robot-3d-map-audit/record.json) · [真实RViz三维结果展示](../../results/reference/robot-3d-map-review-v2/execution.mp4)。展示使用已算好的结果，灰色是静态或未评分边界点、红色是可信标注的残留动态点；显示每六点取一点，评分使用全部有可信标签的点。

## 已做的单因素排查

所有设置均保留，未只展示最好结果；即使采用全部128帧建图，评分仍查询同一批60帧点。

| 方法／只改变的设置 | 静态点保留 | 动态点去除 |
| --- | --- | --- |
| DUFOMap：原设置，0.1m体素 | 99.998% | 46.59% |
| DUFOMap：使用全部128帧 | 99.998% | 51.34% |
| DUFOMap：体素改为0.2m | 99.998% | 50.92% |
| BeautyMap：原设置，8m查询／0.2m高度格 | 81.15% | 74.36% |
| BeautyMap：查询扩大为12m | 76.89% | 77.67% |
| BeautyMap：使用全部128帧 | 80.84% | 73.84% |
| BeautyMap：高度格改为原库默认0.5m | 89.87% | 42.93% |

增加时序观测、放大体素能略提高DUFOMap的去动态率，但没有解决全部残留。BeautyMap扩大查询范围反而加重静态损失；加粗高度格则以去动态能力下降换取静态保留。这些检查只测地图分类，未将消融配置重新用于定位，不能声称它们降低了定位误差。

## 为什么这些场景不容易显出定位收益

| 场景 | 实测支持的解释 | 仍需验证的推测 |
| --- | --- | --- |
| 纯静态 | 没有运动污染需要清理；Raw／DUFOMap的二维图相同，三维仅少1个0.1m占据体素 | BeautyMap损失的静态结构是否影响特定位置的约束 |
| 运动障碍物 | 污染仅约1.03%；DUFOMap已去除部分动态，BeautyMap有显著静态损失；三维仍无明显定位增益 | 大量静态墙面及GICP自身的匹配策略可能已压低动态点影响；需严格相同扫描历史和多轮对照定量分离 |
| 持久变化 | 使用冻结的静态A地图，B中没有重新调用清理或更新；路线也未诱发明显定位失效 | 更强的路线／变化覆盖是否会暴露旧地图不匹配 |
| 走廊退化 | 无动态污染可清，Raw／DUFOMap三维图完全相同；完整观测控制也出现输出中断 | 平行墙的纵向歧义、1m初值偏移、GICP局部匹配及启动／输入历史差异共同作用；当前不能分配各自责任 |

二维投影确实会掩盖部分三维变化：本次动态地图中DUFOMap少161个0.1m体素，但二维仅变化50像素；走廊BeautyMap少68个三维体素，二维变化0像素。一个XY格只要仍有保留点就继续占据，随后的一格膨胀也会遮住细小缺口。不过直接使用三维地图仍没有改善定位，所以投影不是充分解释。

## 论文到底适不适用

[DUFOMap原文§III／§V-E](https://arxiv.org/html/2403.01449v1#S5.SS5)的核心条件是某区域至少一次被完整观测为空；稀疏扫描会降低动态去除率。原文也测试16线半室内数据，不能仅凭“16线／室内”就断言论文不适用。本轮部分去动态成功、加密时序和增大体素的有限改善，与其保守空闲空间判定相符，但不是唯一原因的证明。

[BeautyMap原文§IV／§V](https://arxiv.org/html/2405.07283v1#S4)主要评价三维地图的静态保留和动态去除，包含KITTI与16线半室内数据；长期变化检测和地图更新属于其未来工作。当前小场景、低位雷达、查询尺度及高度格对结果敏感，原生代码和已披露边界适配仍需作为部署条件看待。现有结果能说“当前配置损失静态点且未改善定位”，不能说“论文已被证明不适用”。

三维保留高度、遮挡与空间空闲证据，理论上有利于动态清理；它不会自动补出走廊缺失的几何约束，也不会把冻结旧地图变成在线更新。IR-MCL、AdaM-MCL本身是二维定位方法，不能因切换三维点云就直接复用原模型；本轮三维对照检验的是DUFOMap／BeautyMap地图对GICP的下游收益。

[录制失败、真值复制恢复和末尾未完整写入行的处理记录](../../results/analysis/map-2d-3d/diagnostics.json)保留了未发布录像的原生评分与来源哈希。正式录像按完整性选择，未按误差高低选择；原始会话在本机保留。
