# srrg_mapper2d：原生二维动态环境建图

[实践入口](../HOME.zh-CN.md#srrg-2d) · [极简 GIF 表](../MINIMAL.zh-CN.md)

Lázaro、Capobianco、Grisetti，*Efficient Long-term Mapping in Dynamic Environments*，IROS 2018。[论文记录与开放版 PDF](https://iris.uniroma1.it/handle/11573/1340118) · [作者建图库](https://gitlab.com/srrg-software/srrg_mapper2d) · [ROS 入口](https://gitlab.com/srrg-software/srrg_mapper2d_ros) · [二维配准与合并代码](https://gitlab.com/srrg-software/srrg_scan_matcher)。

| 项目 | 原文适用条件 | 本次场景的差别 |
| --- | --- | --- |
| 传感器 | 连续二维激光点云，轮式里程计作配准初值／先验 | 使用实际 Gazebo `/scan` 和轮式里程计；不使用三维雷达或真值配准 |
| 地图 | 带法向的局部点云、位姿图；跨帧融合及图维护 | 单次短路线；不能覆盖长期、多次会话的全部结论 |
| 原文数据 | LCAS–STRANDS 长期照护场所记录；MIT Stata Center 多次室内采集 | 理想传感器、短路线、人工设置动态箱体及走廊 |
| 动态处理 | 后续观测提供自由空间证据，替换过时点、融合稳定结构 | 没有再次看见旧位置，就缺少删除残影的证据；当前障碍物仍应保留 |
| 定位 | 原文多会话使用已知初始位置 | 本次只给定起点坐标系锚点；不把地图清理当作全局重定位算法 |
| 退化 | 依赖可配准的二维几何及足够观测 | 平行墙难约束沿走廊方向；删除动态点无法创造缺失几何 |

本次调用作者 `Mapper2D`、`LaserMessageTracker`、投影合并与位姿图，外加 ROS2 消息传输／RViz 显示适配。主组使用作者默认关闭图合并的配置，局部动态点融合开启；另做图合并开启组并保留数值失败。持久变化组实际加载静态A图，调用作者多会话入口。不是把自己的过滤器命名为 SRRG，也不宣称复现原文全部长期实验。

编译需要两类兼容修复：OpenCV2 名称改为 OpenCV4 API；移除部分库单独设置的 `-march=native`，使 Eigen 对象布局与 core／发行版 g2o 一致。第一次运动更新崩溃源于这个 ABI 不一致。另将作者写到 stdout 的诊断输出与传输协议分开。这些修复不改变配准、删除或合并规则。[可重建脚本](../../src/scripts/presentation/srrg/build.py)。

作者 `Mapper2D::compute` 拒绝少于 100 束的扫描。因此退化兼容组保留 720 个原生角度格，只在与旧实验相同的 72 个选中束位保留实测值，其余无效；有效距离限制 3.5 m，录制开始 50 s 后恢复。没有插值补点。此组和直接传入 72 项数组应明确区分，后者入口本身不适用。

地图指标采用观测支持覆盖：静态支持按 10 cm 唯一格采样，以 15 cm 判断融合后的地图是否覆盖；动态残影仅评价后来被真实扫描射线验证为空的历史动态位置，排除当前障碍物和静态支持重叠位置。原始累计图使用各帧当时的估计位姿；SRRG 图还包含图优化。因此这是端到端地图维护对照，不能单独归因于点删除模块，也不能与三维原点保留率直接排名。

| 本次观察 | 判断与适用边界 |
| --- | --- |
| 运动障碍物：动态残影删除42.31%，静态覆盖保留99.51% | 原生二维局部融合有效；仍有历史残影，不能宣称完全清理 |
| 持久变化：新增结构覆盖98.90% | 旧图加载与更新确实执行；该场景只增加结构，不能据此验证消失结构的删除 |
| 走廊：首次跟踪重置11.1s，静态覆盖82.24%，Raw83.43% | 本次无清理收益；稀疏扫描影响法向和对应关系，平行墙缺少沿走廊方向约束；删除点不能补充几何 |
| 图合并开启动态图：最后成功66.0s后崩溃 | g2o报Cholesky／协方差分解失败。默认关闭组完整结束，提示图维护／数值兼容问题；独立会话不足以证明单一因果，更不是论文整体不适用的证据 |

这组证据支持将“清理动态残影”和“退化检测／恢复”分成两个问题。前者可用原生二维时间融合；后者需要保留弱方向不确定性、积累跨帧信息，或主动看见端墙／转角。二维雷达＋深度相机的既有 H1–H3 结果继续保留在文章末尾：深度没有在每种场景都带来收益，不能把增加维度当作自动解决方案。
